# Changes to code that a build with a GIL compiles, accepted one by one.
#
# The free-threading series is supposed to leave such a build alone;
# `gil_view.py --check` fails for every file whose GIL view shows changed
# code, unless a line here accepts exactly that change:
#
#     <path>  <digest printed by --check>  <why a GIL build may see this>
#
# The digest covers the changed code lines of the file, so an entry stops
# matching as soon as the change grows - it is then reported as STALE ALLOW.
# An entry nothing matches any more is reported as UNUSED ALLOW. Both fail.
#
# Only a rewrite that does the same thing in other words belongs here. A
# difference a GIL build can observe does not: it goes behind
# Py_GIL_DISABLED, or out of the series. What the helpers named below come
# down to without Py_GIL_DISABLED:
#
#     PepDict_GetItemOwned(d, k)       Py_XNewRef(PyDict_GetItem(d, k))
#     PepDict_GetItemStringOwned(d, k) Py_XNewRef(PyDict_GetItemString(d, k))
#     PepDict_IterationSnapshot(d)     Py_NewRef(d)
#     PepMroRef / PepBasesRef          the tp_mro / tp_bases slot, held for
#                                      the walk, as find_name_in_mro() did
#     SBK_FAILPOINT / SBK_FAILPOINT_THROW  the inventories are empty, so no
#                                      point ever arms
#
# A holder answers null only where the slot is null, which no ready type has,
# so the error branches those additions bring cannot be reached there.
